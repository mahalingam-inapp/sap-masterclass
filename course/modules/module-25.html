Module 25: Business Warehouse / Business Intelligence (BW/BI)

For beginners: BW (Business Warehouse) is SAP’s on‑premise data warehouse. Data is extracted from ERP (FI, CO, MM, SD, etc.), transformed and loaded into BW objects (DataStore Objects, InfoCubes, CompositeProviders). Reporting is done with BEx, Analysis for Office, or SAC (connected to BW). BW is a separate analytical layer—reporting and planning use BW data so that heavy queries do not slow down the transactional system. BW/4HANA is the HANA-based version. Many customers still use BW alongside S/4HANA; others move to SAP Datasphere (Module 21) for cloud. Key terms: ETL, DSO, InfoCube, BEx.

SAP BW and BW/4HANA provide ETL, data modeling, and reporting. BW sits in the data plane as an analytical layer.

Purpose and scope

BW answers: “Where do we get reporting data from transactional systems, and how do we model it for analysis?” Key areas: Extraction: DataSources and extractors pull data from S/4HANA/ECC (e.g. FI documents, SD sales, MM movements). Modeling: InfoObjects (characteristics and key figures); DSO (DataStore Object) for staging and persistent storage; InfoCubes (classic) or CompositeProvider/Open ODS (modern) for multidimensional reporting. Loading: DTP (Data Transfer Process) and transformation rules. Reporting: BEx query, Analysis for Office, SAC (connected to BW as a source).

Features in detail

  • InfoObjects: Reusable building blocks: characteristics (e.g. company code, cost center, material) and key figures (amount, quantity). Used in DSO, cubes, and queries.
  • DSO (DataStore Object): Persistent storage with key (e.g. document, item). Data can be overwritten (e.g. change log) or aggregated. Used for staging and as source for CompositeProvider.
  • CompositeProvider / Open ODS: Modern BW: combine multiple sources (DSO, InfoProvider, external) into one semantic layer for reporting. Replaces classic MultiProvider in many scenarios.
  • Extraction: DataSource in source system (S/4HANA); replication to BW; transformation and DTP load into DSO or InfoProvider. Full and delta extraction.
  • BEx and SAC: BEx query designer builds queries on InfoProviders; Analysis for Office and SAC consume these queries or connect to BW for ad-hoc analysis.

Data plane and control plane

Data plane: BW database holds DSO, InfoCubes, CompositeProvider data; extraction reads from ERP. Reporting queries run against BW objects. Control plane: RSA1 (BW modeling); process chains and DTP for load; authorizations (BW roles); monitoring (RSA1, job overview). See Module 1.

Deployment and integration

Deployment: BW/4HANA on‑premise (or hosted); runs on HANA. Integration: Data from S/4HANA (FI, CO, MM, SD, etc.) via extractors; can feed SAC and Datasphere. SAP recommends Datasphere for new cloud analytics; BW remains for existing BW content and on‑premise reporting.

Example: FI revenue in BW for reporting

Finance wants a BW report showing revenue by company code and month.

  1. DataSource (S/4HANA): Standard FI DataSource for G/L line items (or revenue-specific) is activated in S/4HANA. It provides fields: company code, fiscal year, period, account, amount, etc. Replicate DataSource to BW.
  2. Modeling (BW): Create transformation from DataSource to DSO (e.g. map company code, period, revenue account, amount). Create DTP and load (full then delta). Build CompositeProvider or BEx query on top: dimensions = company code, time; key figure = revenue. Save query.
  3. Reporting: User runs BEx query or opens Analysis for Office / SAC connected to BW. Sees revenue by company code and month. Data is refreshed by load schedule (e.g. nightly delta).

Result: One analytical layer in BW; reporting without querying transactional tables directly.

Key concepts and T-codes

RSA1: BW modeling (InfoArea, InfoProvider, transformation, DTP). Process chain: Scheduled sequence of loads and jobs. Delta extraction: Only new/changed records since last run. BW vs Datasphere: BW = on‑premise data warehouse; Datasphere = cloud data warehouse and semantic layer (Module 21). Both can feed SAC.

  • B) FI, CO, MM, SD, and other ERP modules

  • D) Only Basis

Q4: What is a DTP in BW?

  • A) Only a sales order
  • B) Data Transfer Process—loads data from source to target (e.g. DSO)
  • C) Only a purchase order
  • D) Only a G/L account
Correct: B
DTP = Data Transfer Process; executes the load with transformation and filters.
