Module 21: SAP Datasphere

For beginners: Datasphere is SAP’s cloud data warehouse and semantic layer. Instead of each report connecting directly to S/4HANA, SuccessFactors, or Ariba (each with different table names and meanings), you bring data into Datasphere and build one business-friendly layer: spaces (logical areas), tables and views, and perspectives (views tailored for reporting). SAC and other tools then connect to Datasphere so that “revenue” or “customer” means the same everywhere. Datasphere runs on BTP (cloud only). Key terms: space, entity, perspective, semantic layer.

SAP Datasphere integrates data from S/4HANA and cloud sources into a unified semantic layer for SAC and other consumers.

Purpose and scope

Datasphere provides: Data integration: Connect to S/4HANA (OData, ABAP CDS), SuccessFactors, Ariba, files, and more. Replicate or virtualize data. Modeling: In a space, create local tables (from replication or ETL), views (graphical or SQL), and semantic layer (business entities, dimensions, measures). Perspectives: Expose a subset of the model to consumers (e.g. “Revenue” perspective for SAC) with proper semantics. Consumption: SAC connects to Datasphere via live connection; S/4HANA can consume Datasphere for embedded analytics; external BI tools can connect via SQL or APIs. Datasphere replaces or complements BW for many cloud-first analytics scenarios.

Features in detail

  • Spaces: A space is a logical container: data connections (source systems), replicated or virtual tables, views, and perspectives. Access can be restricted by space.
  • Connections and replication: Connect to S/4HANA (via connector), SuccessFactors, Ariba, etc. Data can be replicated (copy) or accessed via virtual tables (query at runtime).
  • Modeling: Build views (graphical builder or SQL) that join and transform data. Define business entities (semantic layer) so that “Revenue” or “Customer” has one meaning across sources.
  • Perspectives: A perspective is a published view for consumption—e.g. “Revenue by region” for SAC. Consumers see only what is in the perspective; semantics (labels, hierarchies) are consistent.
  • Business builder: Prebuilt content (e.g. SAP Analytics content for S/4HANA) can be deployed into a space to jump-start models.

Data plane and control plane

Data plane: Datasphere stores replicated data (in its cloud DB) and metadata (views, perspectives, semantics). For virtual access, data stays in source; Datasphere queries on demand. Control plane: BTP subaccount; spaces and authorizations; connection definitions. See Module 1.

Deployment and integration

Deployment: BTP service; cloud only. Integration: Sources: S/4HANA, SuccessFactors, Ariba, Concur, files, and more. Consumers: SAC (primary), S/4HANA (embedded analytics), BW, external tools (SQL, OData). CPI can be used for custom ETL into or out of Datasphere (Module 22, 29).

Example: Revenue view in Datasphere for SAC

Company wants one “Revenue” definition from S/4HANA and CX for SAC.

  1. Connection (Datasphere): Create connection to S/4HANA (OData or ABAP CDS). Create connection to CX (if needed). In a space, add remote tables or views from S/4HANA (e.g. billing document, revenue G/L). Replicate or use virtual.
  2. View (Datasphere): Build view “Revenue_Actual”: join billing and G/L data; dimensions = company code, region, product, time; measure = revenue amount. Add semantics (currency, aggregation). Create perspective “Revenue” and publish this view.
  3. SAC (Module 20): In SAC, create live connection to Datasphere. Select perspective “Revenue.” Build story with chart “Revenue by region and month.” Data is queried from Datasphere (and thus from S/4HANA) at runtime.

Result: One semantic definition of revenue; SAC and other consumers use it consistently.

Datasphere object types

ObjectPurpose
SpaceContainer for connections, tables, views, perspectives
ConnectionLink to source (S/4HANA, SuccessFactors, etc.)
View / EntityModeled data (join, transform, semantics)
PerspectivePublished view for consumers (SAC, etc.)

Key concepts

Space: Logical boundary; one space can hold multiple sources and models. Semantic layer: Business meaning (entity, measure, dimension) so that “Revenue” or “Customer” is consistent. Perspective: What you expose to SAC or other tools. Datasphere vs BW: Datasphere = cloud, multi-source, semantic layer; BW = traditional SAP data warehouse. Many new analytics landscapes use Datasphere + SAC.
