Module 24: ABAP Basics

For beginners: ABAP is SAP’s programming language. Custom reports, enhancements to standard transactions, forms, workflows, and APIs (OData, BAPI) are typically written in ABAP. In S/4HANA and ECC, ABAP runs in the same system as FI, MM, SD, etc., and can read/write their tables (e.g. BKPF, VBAK). Development is done in a dev system and moved to production via transport requests. SAP’s strategic direction is clean core: new extensions should run on BTP using ABAP Cloud (BTP ABAP environment), which talks to S/4HANA only through released APIs—no direct access to ERP tables. Key terms: ABAP, Data Dictionary (DDIC), transport, ABAP Cloud.

ABAP is used for reports, enhancements, forms, workflows, and APIs. It runs in the data plane and is governed by the control plane (transports, authorizations).

Purpose and scope

ABAP is used to build custom reports (e.g. list of orders by plant), enhance standard behavior (BAdIs, user exits), expose OData and BAPIs for Fiori and external systems, and implement workflows and forms. The Data Dictionary (DDIC) defines tables, views, structures, and data elements used by ABAP and by the application. Development is done in a development system and moved to quality and production via transport requests. Key concepts: transparent table, ABAP program (report, class, function module), debugging (ABAP Debugger), and release strategy for APIs (e.g. OData services).

Features in detail

  • Data Dictionary (SE11): Create and maintain tables (DD02L, DD03L), views, data elements, domains. Tables are the basis for persistent storage; ABAP reads them with SELECT and writes with INSERT/UPDATE/DELETE (or via APIs).
  • ABAP Editor and ADT: SE80 (Object Navigator), SE38 (programs), SE24 (classes). Eclipse-based ABAP Development Tools (ADT) for modern development. Write reports (WRITE, ALV grid), classes, and function modules.
  • Modularization: Function modules (SE37), classes (SE24), and methods. BAPIs are function modules that expose business logic (e.g. BAPI_SALESORDER_CREATEFROMDAT2). Called from other programs, Fiori, or external systems.
  • Enhancements: BAdI (Business Add-In), user exit, and enhancement spot allow adding logic without modifying standard code. Important for upgrade stability.
  • OData and Gateway: Expose CDS views or custom logic as OData services for Fiori apps and external consumers.
  • ABAP Cloud (BTP): In the BTP ABAP environment, only released APIs and ABAP Cloud syntax are allowed; no direct access to customer S/4HANA tables. Extensions run on BTP and call S/4HANA via OData/RFC.

Data plane and control plane

Data plane: ABAP programs read/write module tables (BKPF, VBAK, MARA, etc.) and execute business logic. In BTP ABAP, data plane access is only through released S/4HANA APIs and BTP persistence. Control plane: Transport management (SE09, STMS) moves objects between systems; roles (PFCG) control who can run which transactions and reports. In BTP: subaccount, git, and lifecycle management. See Module 1.

Deployment and integration

Deployment: On‑premise / S/4HANA Cloud: development → transport to test → transport to production. BTP ABAP: deploy from repository (e.g. abapGit) via BTP pipeline. Integration: ABAP exposes RFC, BAPI, OData; Fiori and CPI call these. ABAP can consume RFC, HTTP, OData from other systems. Module 29 covers integration patterns.

Example: Custom report reading FI and SD

Requirement: list all billed sales orders with revenue and cost center for the last month.

  1. Design: Data from VBRK (billing header), VBRP (billing item), and FI line items (BSEG or ACDOCA) for revenue and cost center. Join by document number or use CDS view if available.
  2. Develop (SE38 or ADT): ABAP program: SELECT from relevant tables with filters (billing date, company code). Loop and output to ALV grid (CL_SALV_TABLE) or use CDS view + Fiori. Authorization checks (e.g. company code) via SU53 if user lacks access.
  3. Transport: Save in package; create transport request (SE09). Release and export from dev; import in test and prod. Assign transaction code and role so users can run it.

Typical Open SQL in the report (S/4HANA: inline declarations, @ host variables):

SELECT vbeln, fkdat, kunag, netwr
  FROM vbrk
  WHERE fkdat >= @sy-datum - 30
  INTO TABLE @DATA(lt_billing).

LOOP AT lt_billing INTO DATA(ls).
  " Get FI line (e.g. ACDOCA) for cost center
  SELECT SINGLE kostl FROM acdoca
    WHERE rldnr = '0L' AND rbukrs = @ls-bukrs
      AND docnr = @ls-vbeln
    INTO @DATA(lv_kostl).
  " Output: ls-vbeln, ls-netwr, lv_kostl ...
ENDLOOP.

Clean Core: New logic on BTP (ABAP Cloud or other runtimes); S/4HANA core kept standard. BTP ABAP uses only released APIs to talk to S/4HANA.

Key concepts

Transport request: Container for development objects (programs, DDIC, customizing). Export from dev, import into test/prod. BAPI: Business API—function module that performs a business action (e.g. create sales order). DDIC: Data Dictionary—single source for table and structure definitions. ABAP Cloud: Restricted language and APIs for cloud and upgrade stability; used in BTP ABAP environment.

  • B) Released APIs and OData only (no direct ERP tables)
  • C) Only IDoc
  • D) Only MM

Q3: DDIC is:

  • A) Sales order
  • B) Data Dictionary (tables, views, structures)
  • C) Only Concur
  • D) Only Ariba

Q4: What is a BAPI?

  • A) Only a table
  • B) Business API—function module exposing business logic (e.g. create order)
  • C) Only a report
  • D) Only a transaction
Correct: B
BAPI = Business Application Programming Interface; callable from ABAP, Fiori, or external systems.
