Module 42: SAP Build

For beginners: SAP Build is SAP’s low-code and process automation offering. It lets business users and citizen developers create apps, workflows, and automations with little or no traditional coding—using visual designers, drag-and-drop, and pre-built connectors to SAP and other systems. SAP Build is part of the SAP Business Technology Platform (BTP) and includes: SAP Build Apps (build UIs and logic for custom apps), SAP Build Process Automation (workflows, RPA, business rules), and SAP Build Work Zone (build work sites and launch pads that combine SAP and non-SAP apps). Key terms: low-code, workflow, RPA, process automation, BTP.

SAP Build addresses the need for faster delivery of custom solutions and process improvements without large development teams. It runs on BTP (Module 22) and integrates with S/4HANA, SuccessFactors, Ariba, and third-party systems via APIs and pre-built connectors. Solutions are deployed in the cloud and can be extended by professional developers when needed.

Purpose and scope

SAP Build Apps: Create custom web and mobile apps with visual design. Use data from S/4HANA, BTP services, or REST APIs. Include forms, lists, and business logic (formulas, actions). Deploy as standalone apps or embed in SAP Fiori / Work Zone. SAP Build Process Automation: Design workflows (e.g. approval for purchase requisition, onboarding checklist), automate tasks with RPA (robotic process automation—bots that mimic user actions in UIs), and define business rules (e.g. routing rules, validation). Integrate with SAP and non-SAP systems. SAP Build Work Zone: Build role-based “work sites” (pages) that aggregate SAP Fiori apps, SAP Build apps, and external links. One entry point for users. Together: You can build an approval app with Build Apps, trigger a workflow in Process Automation that runs an RPA bot to copy data from a legacy system, and expose everything in Work Zone.

In plain terms: Low-code means you build by configuring and connecting building blocks (screens, buttons, data sources, “if-then” rules) instead of writing code line by line. RPA (robotic process automation) is a “software robot” that logs into an application and performs steps (e.g. copy data from a spreadsheet into a web form) so humans don’t have to do repetitive work.

Features in detail

  • Build Apps (formerly SAP AppGyver): Visual canvas: drag components (inputs, lists, buttons, charts). Bind to data (OData from S/4HANA, REST, BTP destinations). Add logic with formulas and flow (e.g. “on button click, call API and show result”). Responsive layout for web and mobile. No ABAP or JavaScript required for basic apps; optional custom code for advanced cases. Apps run on BTP and can use SAP identity (SSO).
  • Process Automation — Workflow: Model processes with a BPMN-like editor: start event, tasks (user task, service task), gateways (decisions), end event. User tasks create work items in inbox (e.g. “Approve travel request”). Service tasks call APIs (e.g. create document in S/4HANA). Connectors for S/4HANA, SuccessFactors, Ariba, email, etc. Forms for user input. Deploy and monitor running instances.
  • Process Automation — RPA: Record or script “desktop” or “web” automations. Bot opens an application (e.g. browser, Excel), performs steps (click, type, read), and passes data to workflow or system. Use when no API exists or to bridge legacy systems. Bot runs in a managed environment (attended or unattended).
  • Process Automation — Business Rules: Define rules (e.g. “if amount > 10,000 and department = X, then approver = Y”). Call from workflow or from S/4HANA (via integration). Keeps logic out of hard code and easy to change.
  • Work Zone: Create sites and pages. Add tiles that link to Fiori apps, Build apps, external URLs, or widgets. Assign to roles. Users get one place to start their work. Can include process visibility (workflow tasks) and embedded content.

Data plane and control plane

Data plane: Build Apps and Process Automation typically don’t store business data long-term; they read and write via APIs to S/4HANA, Datasphere, or other systems. Workflow instance data (process variables, task state) is stored in BTP. RPA may read/write files or UIs. Work Zone stores page layout and assignments. Control plane: Configuration is in BTP: subaccount, entitlements (Build Apps, Process Automation, Work Zone), destinations to S/4HANA and other backends. Build Apps and Process Automation have their own design-time UIs (no SPRO). Roles and permissions for who can build vs run are managed in BTP and identity provider.

Deployment and integration

Deployment: SAP Build runs on SAP BTP (cloud). Subscribing to Build Apps, Process Automation, and/or Work Zone gives access to the design and runtime environments. No on‑premise installation of “Build” itself; it connects to on‑premise S/4HANA via Cloud Connector if needed. Integration: Connectors to S/4HANA (OData, API), SuccessFactors, Ariba, Concur, and generic REST/SOAP. Process Automation can trigger and be triggered by S/4HANA (e.g. workflow started from Fiori app). Work Zone embeds Fiori and Build apps. See Module 22 (BTP) and Module 29 (Integration).

Example: Approval workflow with Build Process Automation and an app in Work Zone

Scenario: Purchase requisitions above 5,000 EUR must be approved by a manager. Requisition is created in S/4HANA; workflow is triggered (e.g. via event or API from S/4HANA).

Process Automation: Workflow “PR Approval” has: (1) Start when PR created (integration from S/4HANA). (2) User task “Approve PR” — assigned to manager of requester (business rule looks up manager from SuccessFactors or S/4HANA). (3) Form: Approve / Reject, comment. (4) If approved, service task calls S/4HANA API to release PR. (5) If rejected, service task updates PR with rejection reason. (6) End. Email notification to requester. Manager sees the task in Work Zone or Fiori inbox.

Work Zone: Manager’s work site has tiles: “My Inbox” (workflow tasks), “Purchase Requisitions,” “Reports.” One click to open approval task. Build Apps could be used to build a custom “Approval Dashboard” app and add it as a tile.

Key SAP Build components

ComponentPurpose
SAP Build AppsLow-code app development: UIs and logic for custom web/mobile apps; connect to S/4HANA and APIs.
SAP Build Process AutomationWorkflows, RPA (bots), business rules; automate processes across SAP and non-SAP.
SAP Build Work ZoneBuild work sites and launch pads; aggregate Fiori, Build apps, and external links.
RPASoftware robot that automates UI-based tasks (e.g. copy data from legacy app).
Relationship to other modules: BTP (Module 22) is the platform; Build runs on BTP. Integration (Module 29) is used for connectors to S/4HANA and other systems. Fiori (Module 28) apps can be combined with Build apps in Work Zone. S/4HANA (Module 30) is a main data and process source. Activate (Module 41) may use Build for extensions during Realize.
