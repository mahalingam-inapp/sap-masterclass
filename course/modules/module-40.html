Module 40: SAP S/4HANA Migration

For beginners: Moving from an older SAP system (typically ECC on any database) to S/4HANA is a major project. “Migration” here means moving your data, configuration, and custom code to S/4HANA, which runs only on SAP HANA and has a simplified data model (e.g. universal journal in FI, material ledger, no redundant tables). You can do a technical conversion (same system, upgrade and convert in place), a greenfield (new S/4HANA, load only what you need), or a brownfield (selective data migration to a new S/4HANA). Key terms: conversion, greenfield, brownfield, SUM (Software Update Manager), custom code adaptation.

S/4HANA migration is not just an upgrade: the application is redesigned for HANA, and many ECC structures (e.g. separate FI tables, material ledger variants) are replaced or simplified. Migration therefore involves technical steps (database, code), data transformation (e.g. table conversions, new fields), and process/business alignment (Fiori, new processes). SAP provides tools (SUM, DMO, migration tools) and methodology (SAP Activate, see Module 41).

Purpose and scope

Technical conversion (system conversion): Upgrade ECC (on any DB) to S/4HANA on HANA. Same system ID; data is converted in place. Uses SUM (Software Update Manager) and DMO (Database Migration Option) to switch database to HANA and apply S/4HANA changes. Custom code must be adapted (ABAP for HANA, removal of obsolete objects). Greenfield: New S/4HANA system; no historical data migration (or only reference data). Configure from scratch using best practices. Suited to companies that want a clean start or have simple requirements. Brownfield (selective data transition): New S/4HANA system; migrate selected data (e.g. open items, current master data, last N years of documents) from ECC. Combines new design with historical data where needed. Central Finance as stepping stone: Introduce S/4HANA as Central Finance first (replicate from ECC), then later convert or migrate source systems (see Module 39).

In plain terms: Technical conversion = “we keep our one ECC box, switch its database to HANA and turn it into S/4HANA.” Greenfield = “we build a new S/4HANA from scratch and don’t carry over old data.” Brownfield = “we build new S/4HANA but copy over some data (e.g. open orders, master data) from ECC.”

Key migration steps (technical conversion)

  • Readiness and preparation: Run SAP Readiness Check (or equivalent): identifies custom code issues, add-ons compatibility, and configuration gaps. Resolve custom code (ABAP that uses obsolete APIs or tables). Plan for HANA sizing and infrastructure. Decide on Unicode if not already (S/4HANA is Unicode).
  • Software Update Manager (SUM) and DMO: SUM runs the upgrade and conversion. DMO (Database Migration Option) converts the database to HANA (if coming from non-HANA) and runs table conversions (e.g. merge of FI tables into ACDOCA, material document conversions). Downtime is required; duration depends on data volume. Pre-checks and post-checks are part of the process.
  • Custom code adaptation: S/4HANA deprecates many tables and APIs. Custom programs that read/write these must be adapted (e.g. use new CDS views, new APIs). ABAP Test Cockpit (ATC) and custom code checks (e.g. “S/4HANA compatibility”) identify issues. Fix before or during migration; some can be done after with remediation projects.
  • Data conversion and reconciliation: After conversion, verify data: FI totals (G/L, AR, AP), inventory, open orders. Reconciliation reports compare ECC (pre) vs S/4HANA (post). Fix any conversion errors or mapping issues. Business sign-off on key figures is critical.
  • Fiori and UX: S/4HANA emphasises Fiori and SAP GUI for backend. Plan Fiori activation, roles, and catalog. Train users on new transactions and apps. Some ECC transactions are replaced by Fiori apps or simplified transactions.

Data and landscape

Data: In technical conversion, existing tables are converted (e.g. BKPF/BSEG → ACDOCA for FI; material document tables consolidated). Historical data is preserved but stored in the new structure. In greenfield, only master and initial data (if any) are loaded. In brownfield, migration tools (e.g. SAP Data Services, migration objects) extract from ECC and load into S/4HANA with transformation. Landscape: Conversion is typically done in dev → test → prod order (each system converted or cloned and converted). Brownfield and greenfield use new S/4HANA systems; data is migrated or not as per design.

Deployment options

On‑premise: S/4HANA on your own or partner data centre; HANA database on your infrastructure. Conversion or new installation with migration. Cloud: S/4HANA Cloud (public cloud) is a subscription; no “migration” in the same sense—you configure in the cloud and may load data via migration tools or integrate from on‑premise. Hybrid: Central Finance on S/4HANA Cloud with replication from ECC on‑premise; then convert ECC to S/4HANA on‑premise or move to cloud. See Module 30 for S/4HANA overview and Module 41 for SAP Activate methodology.

Example: Technical conversion from ECC 6.0 on Oracle to S/4HANA

Company runs ECC 6.0 EHP 8 on Oracle. They choose technical conversion to S/4HANA 2022 on HANA. Steps: (1) Run Readiness Check; fix 200+ custom code issues (mostly table references to obsolete FI tables). (2) Unicode conversion already done. (3) In maintenance window, run SUM with DMO: export ECC data, install HANA, load data into HANA, run S/4HANA conversion (table splits/merges, new fields). Downtime 36 hours. (4) Post-conversion: run reconciliation (G/L, AR, AP, inventory); a few conversion errors in cost centre assignment—fix with correction postings. (5) Activate Fiori, assign roles, train users. (6) Decommission Oracle; system is now S/4HANA on HANA. Same company codes, same historical data; new data model and UX.

📝 Module Quiz

Q1: What is “technical conversion” to S/4HANA?

  • A) Only greenfield
  • B) Upgrade and convert ECC to S/4HANA in place; same system, database switched to HANA, data and structures converted
  • C) Only brownfield
  • D) Only cloud
Correct: B
Technical conversion keeps the same system and converts it to S/4HANA on HANA.

Q2: Why is custom code adaptation needed for S/4HANA?

  • A) Only for Fiori
  • B) S/4HANA removes or changes many tables and APIs; custom programs that use them must be updated
  • C) Only for SD
  • D) Only for MM
Correct: B
Simplification and new data model require code changes for compatibility.

Q3: What is the main use of SUM in migration?

  • A) Only for reporting
  • B) Software Update Manager runs the upgrade and conversion (including database migration to HANA via DMO)
  • C) Only for FI
  • D) Only for HR
Correct: B
SUM is the standard tool for technical conversion.

Q4: Greenfield vs brownfield: which typically involves migrating historical data from ECC?

  • A) Greenfield
  • B) Brownfield—new S/4HANA with selective data migration; greenfield is new system without old data
  • C) Both equally
  • D) Neither
Correct: B
Brownfield implies migrating selected data; greenfield starts fresh.
