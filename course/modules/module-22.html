Module 22: SAP Business Technology Platform (BTP)

For beginners: BTP is SAP’s cloud platform for integration, extension, and development. It does not replace S/4HANA or SuccessFactors—it is the place where you connect them (e.g. CPI integration flows), expose APIs (API Management), and build custom apps (ABAP Cloud, SAP Build) or use analytics (Datasphere). Think of BTP as the “glue and workshop”: integration (CPI, Event Mesh) is control plane; extensions and Datasphere may have their own data. BTP is cloud only and is organized in global account → subaccount; you enable services (e.g. Integration Suite, Datasphere) per subaccount. Key terms: CPI, API Management, Event Mesh, subaccount.

SAP BTP provides integration, extension, and analytics services in the cloud. It connects S/4HANA and cloud products and hosts custom apps and Datasphere.

Purpose and scope

BTP provides: Integration Suite: CPI (Cloud Integration) for iFlows (A2A, B2B); API Management for APIs; Event Mesh for event-driven integration. Extension Suite: ABAP environment (Steampunk) for ABAP Cloud apps; SAP Build (low-code apps, process automation); other runtimes (e.g. Java, Node). Datasphere: Data warehouse and semantic layer (Module 21). Identity (IAS): SAP Identity Authentication Service for SSO and identity federation. Other services: Workflow, document management, etc. BTP is organized by global account → subaccount → services. Entitlements (what you can use) and region (where it runs) are set at subaccount level.

Features in detail

  • CPI (Cloud Integration): Design iFlows that connect systems: S/4HANA ↔ SuccessFactors, Ariba, Concur, etc. Adapters (OData, REST, IDoc, SFTP, etc.); mapping and routing. Prebuilt content for many SAP-to-SAP scenarios. See Module 29.
  • API Management: Publish APIs (from S/4HANA or BTP apps); apply policies (rate limit, auth); expose to internal or external consumers. Part of Integration Suite.
  • Event Mesh: Publish events (e.g. “Sales order created” from S/4HANA); subscribers (BTP app, CPI) react. Decoupled, event-driven integration.
  • ABAP environment (Steampunk): ABAP Cloud in BTP; develop extensions that call S/4HANA via released APIs. Deploy via BTP (no transport to S/4HANA).
  • IAS (Identity Authentication Service): Central identity for SAP cloud apps; SSO; federation with customer IdP (e.g. Azure AD).

Data plane and control plane

Data plane: BTP itself is mainly control plane. Data lives in: S/4HANA, SuccessFactors, etc. (source systems); Datasphere (analytics); BTP apps (e.g. Steampunk app with its own persistence). Integration flows in CPI move data but do not store it long-term. Control plane: Global account and subaccounts; entitlements and quotas; IAS (who can log on); Integration Suite (which flows, APIs, events); space and service instances. See Module 1.

Deployment and integration

Deployment: BTP is cloud only; you choose region(s) for subaccounts. Integration: BTP is the hub: CPI connects S/4HANA to SuccessFactors, Ariba, Concur, CX, and non-SAP. API Management exposes S/4HANA OData/REST. Event Mesh connects event publishers (S/4HANA, SuccessFactors) and subscribers. IAS provides identity for all SAP cloud apps. Module 29 details integration patterns.

Example: CPI flow from S/4HANA to SuccessFactors

When a new cost center is created in S/4HANA, replicate it to SuccessFactors for org structure.

  1. Trigger (S/4HANA): Cost center 2000 is created (OM or API). S/4HANA can send an event (e.g. via Event Mesh) or CPI polls OData API for new cost centers. Alternatively, S/4HANA calls out to CPI (outbound).
  2. CPI iFlow: iFlow is triggered (by event, schedule, or call). It reads cost center from S/4HANA (OData or RFC). Maps to SuccessFactors format (e.g. cost center as org attribute). Calls SuccessFactors API (OData) to create or update the cost center in EC.
  3. Result: Cost center exists in both S/4HANA and SuccessFactors. FI and HR use the same cost center for posting and org assignment.

Result: One integration flow in BTP; two systems in sync.

Key concepts

Global account / subaccount: Global account = contract; subaccount = where you enable services (CPI, Datasphere, etc.) and choose region. Entitlements: What services and how much (e.g. CPI messages per month). Clean Core: SAP recommends extending on BTP (and using released APIs) instead of modifying S/4HANA heavily. Integration Suite: One place for CPI, API Management, and Event Mesh (Module 29).
