Module 10: Project System (PS)

For beginners: Project System (PS) is the part of SAP that manages projects—internal projects (e.g. R&D, marketing campaigns), capital projects (building a plant, installing machinery), or customer projects. You structure a project with a Work Breakdown Structure (WBS): a hierarchy of phases and work packages. You can add networks (activities with sequence and duration) for scheduling. All costs that belong to the project—materials, external services, labor—are posted to WBS elements or network activities. At period-end, you settle the project: move those costs to the final receiver (e.g. cost center, or fixed asset for a capital project). Key terms: WBS, network, budget, and settlement.

SAP PS supports project and investment management. It integrates with MM (material and service procurement), CO (cost and settlement), and FI (asset capitalization).

Purpose and scope

PS provides a hierarchical project structure (WBS elements), optional network activities (tasks with duration and dependencies), milestones for billing or status, and budgets. Costs are posted to WBS elements or network activities from MM (material, purchase order), internal orders, and direct postings. Period-end settlement moves project costs to the final receiver: cost center, internal order, or asset (capital project). Investment Management (IM) can use PS for appropriation requests and capital spending.

In plain terms: A WBS element is like a cost bucket for one part of the project (e.g. “Phase 1 – Design”). When you buy materials or services for that phase and assign them to the WBS element, the cost is collected there. Settlement then “empties” those buckets into the right place: for example, a construction project might settle to a fixed asset so the building appears on the balance sheet.

Features in detail

  • Project definition (PROJ): Top-level project (e.g. “New Plant 2025”). Contains WBS elements and optionally networks.
  • WBS (Work Breakdown Structure, PRPS): Hierarchical breakdown: project → phases → work packages. Each WBS element can receive budget and cost. Used for planning and reporting.
  • Network (AFKO/AFPO): Activities with sequence (order of execution), duration, and links to materials and services. Used for scheduling and procurement. Milestones can trigger billing or status.
  • Budgeting: Original budget and supplements at WBS level. Availability check prevents overrun (optional).
  • Procurement: Material and external services can be assigned to WBS element or network activity. Purchase orders and goods movements post cost to the project.
  • Settlement: Project costs are settled to cost center, internal order, or asset (e.g. capitalize construction project to fixed asset). Settlement rule defines source (WBS/network) and receiver.

Data plane and control plane

Data plane: Project definition (PROJ), WBS elements (PRPS), networks (AFKO, AFPO), cost (COEP posted to WBS/network). Control plane: Project profile (controls WBS/network usage, settlement), settlement profile, budget profile (SPRO). See Module 1.

Deployment and integration

Deployment: On‑premise and S/4HANA Cloud. Integration: Costs from MM (material, PO), internal orders, and direct postings; settlement to FI/CO (cost center, order, asset); Investment Management (IM) for capital projects.

Example: Capital project — construction of a new building

Project “Building B-2025” with WBS: B-2025 (root), B-2025-01 (Design), B-2025-02 (Construction), B-2025-03 (Commissioning). Budget 2M EUR. Costs are to be capitalized to a fixed asset at project end.

  1. Create project (CJ20N): Project definition B-2025, WBS elements as above. Assign budget to root or to each WBS. Set settlement rule: B-2025 → Asset (AUA) 300000 (Building).
  2. Post costs: External contractor invoice (MM/FI) assigned to WBS B-2025-02: 500,000 EUR. Material issues to WBS for construction. Labor from internal cost center assigned to WBS. All costs collect on WBS elements.
  3. Settlement (CJ88 or period-end): Run settlement for project B-2025. Costs from WBS elements are transferred to asset 300000. FI: asset value increases; CO: project cost cleared. Project can be closed.

Result: All project costs capitalized to the building asset in FI.

Important T-codes and concepts

Project: CJ20N (project builder), CJ03 (display), CN41 (network). Settlement: CJ88 (run settlement). Concepts: WBS vs network; settlement rule (source WBS/activity → receiver cost center/order/asset); budget vs actual.

📝 Module Quiz

Q1: WBS stands for:

  • A) Work breakdown structure
  • B) Warehouse billing system
  • C) Only FI
  • D) Only SD
Correct: A
WBS = Work breakdown structure for project hierarchy.

Q2: PS settlement can go to:

  • A) Only SD
  • B) Only MM
  • C) Only QM
  • D) Cost center, order, asset (FI)
Correct: D
Project costs settle to cost center, order, or asset.

Q3: PRPS holds:

  • A) Sales order
  • B) WBS element
  • C) Purchase order
  • D) Material
Correct: B
PRPS = WBS element; PROJ = project definition.

Q4: Where do project costs originate before settlement?

  • A) Only from SD billing
  • B) From MM (material, PO), internal postings, and other modules posting to WBS/network
  • C) Only from QM
  • D) Only from PM
Correct: B
Costs post to WBS/network from MM, internal orders, and direct postings; settlement moves them to the receiver.
