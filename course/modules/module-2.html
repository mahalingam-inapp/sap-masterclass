Module 2: SAP Overview & Navigation

For beginners: This module is about how you actually use SAP day to day: how you log in, how you find transactions (the programs that do a specific task, like “create a purchase order” or “display a table”), and how the interface is organized. You will hear about SAP GUI (the classic Windows-style interface) and Fiori (the newer web-based apps). You do not need to memorize every transaction code—just understand that each business action has a code (e.g. VA01 = create sales order) and that the same backend data is used whether you work in GUI or Fiori.

This chapter introduces SAP as a platform and basic navigation. It builds on Module 1 (Foundation concepts) for data plane, control plane, deployment, and integration.

What is SAP ERP / S/4HANA?

SAP ERP is an enterprise resource planning suite: one integrated system for finance, procurement, sales, production, and more. S/4HANA is the current generation of that suite, built on the SAP HANA database. It has a simplified data model, real-time analytics, and a modern user experience (Fiori). Deployment options: on‑premise (in your data center), S/4HANA Cloud (SAP or partner hosts it), and hybrid—see Module 1. As a beginner, think of S/4HANA as “the main SAP system” where most of the core business runs.

Features

  • Logon and clients: Users log on to a client (a three-digit number, e.g. 800 for sandbox or development, 100 for production). The client defines data isolation: data in client 800 is separate from client 100, so you can have development and production in the same system without mixing data.
  • SAP GUI vs Fiori: SAP GUI is the classic interface: you run transactions (each has a code, e.g. SE16 for browsing table data). Fiori is the newer interface: role-based apps (e.g. “Manage My Invoices”) that run in the browser or on mobile. Both talk to the same backend; Fiori often bundles several transactions into one app.
  • Menu and favorites: The menu (e.g. Easy Access) shows transactions by area (Accounting, Logistics, etc.). You can also type a transaction code (T-code) in the command field and press Enter. Adding transactions to Favorites gives one-click access.
  • Work centers: In Fiori, work centers group apps by role (e.g. “Financial Accountant”) so users see only what they need.

Data plane & control plane (recap)

In ERP, the data plane is the database and application server (tables, business logic). The control plane is Basis (client, transport), customizing (SPRO), and security (users, roles). See Module 1 for full definitions.

Interactions

Two end-to-end processes you will see often: Order to cash (O2C)—Sales (SD): customer order → delivery → billing → money recorded in FI (Accounts Receivable and Revenue). Procure to pay (P2P)—Purchasing (MM): requisition → purchase order → goods receipt → vendor invoice → money recorded in FI (Accounts Payable and expense/inventory). Document flow links the steps: one sales order leads to one or more deliveries, then to billing, then to an FI document. Integration detail is in Module 29.

In plain terms: “Document flow” means the system links related documents (e.g. this invoice was created from that delivery, which came from that order). So you can trace any invoice back to the original order and see the full story. This is why FI does not need to re-enter data—it gets it automatically from SD or MM.

Tables and navigation concepts

Business data lives in transparent tables (Data Dictionary, transaction SE11). You browse table contents with SE16 (Data Browser) and maintain config tables with SM30. The client (e.g. 800 = development/sandbox, 100 = production) isolates data and customizing so that multiple “tenants” can run on one system. Roles and authorizations (PFCG, SU53) control which transactions and data each user can access. Use SAP Help and SAP Learning Hub for deeper learning.

Example: From logon to running a transaction

A typical path a user takes:

  1. Logon: SAP GUI or Fiori launchpad; user enters system, client (e.g. 800), user ID, and password.
  2. Menu: Easy Access menu shows role-based nodes (e.g. Accounting → Financial Accounting → General Ledger). User can also type a transaction code in the command field (e.g. SE16) and press Enter.
  3. Favorites: Users add frequently used transactions to Favorites (right-click → Add to Favorites) for one-click access.
  4. Work center (Fiori): In S/4HANA, Fiori apps are grouped by role (e.g. “Manage My Invoices,” “Display G/L Account Balance”). One app may replace several classic transactions.

Same business function can be reached via SAP GUI (transaction code) or Fiori (app); the backend (data plane and control plane) is the same.

📝 Module Quiz

Question 1: What does “client” mean in SAP?

  • A) A customer in SD
  • B) A self-contained unit for data and configuration (e.g. 800)
  • C) Only S/4HANA Cloud
  • D) The control plane only
Correct Answer: B
The client is a logical unit that isolates data and customizing; users log on to a client.

Question 2: Where is business data processed in ERP?

  • A) Only in the control plane
  • B) In the data plane (database and application server)
  • C) Only in Fiori
  • D) Only in Basis
Correct Answer: B
Data plane = where data is stored and processed (DB + app server).

Question 3: Order to cash typically involves which modules?

  • A) Only MM
  • B) SD (order, delivery, billing) and FI (revenue, AR)
  • C) Only CO
  • D) Only Basis
Correct Answer: B
SD handles sales order, delivery, billing; FI records revenue and receivables.
