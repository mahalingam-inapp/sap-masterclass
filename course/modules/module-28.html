Module 28: Fiori & User Experience

For beginners: Fiori is SAP’s modern, web-based UI. Instead of the classic SAP GUI (transaction-based), users open the Fiori Launchpad in the browser and see tiles (one per app). Each app does one thing—e.g. “Manage Purchase Orders” or “Display G/L Account Balance”—and connects to S/4HANA via OData or BAPI. The same backend data is used; only the way users reach it changes. Fiori can run embedded in S/4HANA or on BTP (Launchpad service). Key terms: Fiori Launchpad, tile, catalog, OData.

Fiori provides role-based, responsive apps that connect to S/4HANA via OData and BAPIs. The UI layer is control plane for how users reach the data plane.

Purpose and scope

Fiori provides: Fiori Launchpad: Home page with catalog (groups of apps), tiles (one per app), and role-based visibility. User logs on once and sees only the apps assigned to their roles. Fiori apps: Standard apps (from SAP) and custom apps. Each app is typically one transaction or one use case; it calls the backend via OData or BAPI. Fiori design: Guidelines for layout, controls, and responsiveness. SAP Build: Low-code option to build Fiori-like apps. SAP GUI and Web GUI: Classic UI still used for some transactions; Fiori is the strategic direction for new and refreshed UX.

Features in detail

  • Launchpad: Central entry; catalog defines which apps (tiles) appear. Tiles can be static (link to app) or dynamic (e.g. count of open items). Role determines which catalog groups and tiles the user sees. Embedded Launchpad in S/4HANA or BTP Launchpad service (which can show apps from S/4HANA and from BTP).
  • Standard Fiori apps: SAP delivers hundreds of apps (e.g. “Create Sales Order,” “Manage Purchase Orders,” “Display G/L Account Balance”). They consume OData services or BAPIs from S/4HANA. Activate and assign to catalog/role.
  • Custom Fiori apps: Build with SAP Fiori elements (template-based on CDS/OData) or SAPUI5 freestyle. Expose OData service in S/4HANA (from CDS view or custom); app calls it. Deploy to S/4HANA (embedded) or BTP.
  • Gateway and OData: SAP Gateway (in S/4HANA or standalone) exposes OData services. Fiori apps are Gateway clients. BAPI can also be called from Fiori (e.g. for create/save).

Data plane and control plane

Data plane: Data stays in S/4HANA (or other backend). Fiori apps only display and send requests; they do not store business data. Control plane: Launchpad catalog, groups, and tiles; role assignment (which users see which apps); Gateway/OData service registration and authorization. See Module 1.

Deployment and integration

Deployment: Embedded Fiori: Launchpad and apps run in S/4HANA (same system as backend). BTP Launchpad service: Launchpad runs on BTP; apps can be from S/4HANA (federated) or from BTP. Integration: Fiori apps call S/4HANA via OData and BAPIs; IAS for SSO when using BTP or multiple systems (Module 22, 29).

Example: User opens “Display G/L Account Balance” in Fiori

Accountant uses Fiori instead of transaction S_ALR_87012284.

  1. Logon and Launchpad: User logs on to Fiori Launchpad (embedded in S/4HANA or BTP). Launchpad shows tiles based on user’s roles. User clicks tile “Display G/L Account Balance.”
  2. App and OData: Fiori app loads. It calls an OData service (e.g. /sap/opu/odata/sap/API_...) that reads G/L balance data from S/4HANA (e.g. from CDS view or BAPI). Request is sent over HTTP(S); backend returns JSON. App displays the data in a table or chart.
  3. Authorization: Backend (S/4HANA) checks user’s authorizations for the OData service and underlying data (e.g. company code). If OK, data is returned; otherwise error. Same principle as transaction authorization.

Result: Same data as classic transaction; modern UI and one launchpad for many apps.

Key concepts

Tile and catalog: Tile = link to an app; catalog = set of tiles. Role determines which catalogs and tiles are visible. OData: RESTful API; Fiori apps typically use OData to read and write. Embedded vs BTP Launchpad: Embedded = everything in S/4HANA. BTP Launchpad = launchpad on BTP; can show apps from S/4HANA (federated) and from BTP. SAP GUI: Classic UI still used; Fiori is the strategic UX for new and refreshed scenarios.

📝 Module Quiz

Q1: Fiori apps typically call the backend via:

  • A) Only IDoc
  • B) OData and BAPIs
  • C) Only RFC
  • D) Only batch input
Correct: B
Fiori uses OData and BAPIs to talk to S/4HANA.

Q2: Fiori Launchpad provides:

  • A) Only MM transaction
  • B) Central entry point (catalog, tiles, role-based apps)
  • C) Only FI
  • D) Only CO
Correct: B
Launchpad = single entry with catalog and tiles.

Q3: Fiori can run:

  • A) Only on-premise SAP GUI
  • B) Embedded in S/4HANA and on BTP (Launchpad service)
  • C) Only in BW
  • D) Only in Basis
Correct: B
Fiori runs in S/4HANA or BTP Launchpad.

Q4: What is SAP Gateway used for in Fiori?

  • A) Only material master
  • B) Exposing OData services from S/4HANA for Fiori and other clients
  • C) Only SD delivery
  • D) Only production order
Correct: B
Gateway hosts and exposes OData services that Fiori apps consume.
