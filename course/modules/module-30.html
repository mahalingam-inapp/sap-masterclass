Module 30: SAP S/4HANA Overview

For beginners: S/4HANA is SAP’s current ERP suite. It runs on the SAP HANA database and includes FI, CO, MM, SD, PP, QM, PM, PS, and more in one system. It has a simplified data model (e.g. one table for FI/CO line items), real-time reporting, and Fiori as the main UI. S/4HANA is the “digital core”—the single source of truth for transactional data—and is designed to work with cloud products (SuccessFactors, Ariba, Concur) and BTP. You can run it on‑premise (your data center), as S/4HANA Cloud (SAP or partner hosts), or hybrid. Key terms: S/4HANA, HANA, digital core, Fiori-first.

SAP S/4HANA combines core ERP modules in one system with a simplified data model, real-time analytics, and Fiori. Deployment: on‑premise, cloud, or hybrid.

Purpose and scope

S/4HANA delivers: Simplified data model: Redundant tables and indices removed; e.g. ACDOCA (universal journal) holds FI and CO line items in one table. Real-time: No separate batch aggregation for many reports; HANA allows direct query on transactional data. Fiori-first: New and refreshed transactions as Fiori apps; SAP GUI still available. Cloud readiness: APIs (OData, BAPI), events, and extension on BTP. Embedded analytics: CDS views and embedded BW-style reporting. All modules (FI, CO, MM, SD, PP, etc.) are part of one S/4HANA system; no separate “ECC” for S/4HANA—it is the successor to ECC.

Features in detail

  • Universal journal (ACDOCA): Single table for FI and CO posting line items (replacing multiple aggregate tables). Simplifies reporting and reconciliation.
  • HANA database: In-memory; columnar storage; no need for many indexes and aggregates for reporting. Enables real-time analytics on live data.
  • CDS (Core Data Services): Semantic data model; CDS views expose data for Fiori, analytics, and APIs. Replaces or complements classic views and extractors.
  • Fiori and SAP GUI: Fiori is the strategic UX; SAP GUI (and Web GUI) remain for classic transactions. Transaction codes still work; Fiori apps often replace them for key tasks.
  • S/4HANA Cloud: SAP (or partner) operates the system; subscription model; quarterly updates. Limited customizing (extensibility via BTP and key user tools). Same modules, different operations model.

Data plane and control plane

Data plane: HANA database; tables such as ACDOCA, BKPF, BSEG, VBAK, MARA, etc. (simplified and new in S/4HANA where applicable). Application server runs ABAP and business logic. Control plane: Basis (client, transport, jobs), customizing (SPRO), security (users, roles), and integration (RFC, OData, events). BTP for extension (Module 22). See Module 1.

Deployment and integration

Deployment: On‑premise (customer or partner hosts); S/4HANA Cloud public (SAP-operated, multi-tenant); S/4HANA Cloud private (dedicated). Hybrid: S/4HANA + BTP + cloud products. Integration: CPI, API Management, Event Mesh connect S/4HANA to SuccessFactors, Ariba, Concur, CX, IBP, and non-SAP. Fiori and OData for user and app access. Module 29.

Example: One posting, one table (ACDOCA)

In S/4HANA, a vendor invoice posting creates one set of line items in the universal journal.

  1. Posting (e.g. MIRO or FB01): User posts vendor invoice: 1,000 EUR to cost center 1000. In ECC, this would create entries in multiple tables (e.g. BSIS, BSAS, line item tables per ledger).
  2. S/4HANA (ACDOCA): One document; line items are written to ACDOCA (universal journal). Each line has company code, account, amount, cost center, fiscal year, period, etc. FI and CO reporting read from the same table. No separate reconciliation step for FI–CO.
  3. Reporting: Report or Fiori app queries ACDOCA (or CDS view on top) with filters. Real-time; no batch aggregation. G/L balance, cost center report, and P&L use the same source.

Result: Simplified model; one source of truth; real-time reporting.

Fiori-first: New and refreshed UX as Fiori; classic transactions still available. Clean core: Minimize customizing in S/4HANA; extend on BTP.
