Module 26: SAP Basis

For beginners: Basis is the technical layer that makes the SAP system run: client, application server, database, transport (moving changes from dev → test → prod), background jobs, monitoring, and upgrades. It is part of the control plane: Basis does not hold business data, but it defines which systems exist, how they are connected, and how customizing and code are promoted. In on‑premise S/4HANA, your team (or a partner) does Basis; in S/4HANA Cloud, SAP operates it. Key terms: client, instance, STMS (transport), application server.

SAP Basis covers system administration for NetWeaver (S/4HANA, ECC, BW). The data plane runs on the infrastructure Basis configures and maintains.

Purpose and scope

Basis ensures that the SAP system is installed, configured, and running: Client: Logical unit (e.g. 800 development, 100 production) that isolates data and customizing. Instance and application server: One or more app servers connect to one database; load balancing and profiles. Transport (STMS): Move development and customizing from dev → test → prod. Background jobs: Schedule reports and cleanup. Spool: Print and output management. Monitoring: System log (SM21), workload, locks (SM12), and CCMS. Patch and upgrade: Support packages and release upgrades. Basis works closely with Security (Module 27) for users and authorizations and with Integration (Module 29) for RFC and connectivity.

Features in detail

  • Client: Mandatory at logon. Data and customizing are client-dependent (or client-independent for cross-client data). Client copy (SCC1) duplicates a client; client transport exports/imports client data.
  • Transport Management (STMS): Transport domain links systems (dev, test, prod). Development objects and customizing are assigned to transport requests. Export from source, import into target. Transports are the only way to promote ABAP and customizing in a controlled manner.
  • Background jobs (SM37): Schedule ABAP programs, reports, and external commands. Define job name, steps, and schedule (date/time or periodic). Monitor with SM37.
  • RFC (SM59): Remote Function Call destinations for system-to-system communication. Used by CPI, PI/PO, and other SAP systems to call this system (or vice versa).
  • Monitoring: SM21 (system log), SM50 (work processes), SM12 (locks), ST22 (ABAP dump). CCMS for centralized monitoring and alerts.

Data plane and control plane

Data plane: The database (HANA or legacy) and application server run the business logic and store data. Basis does not own the business data—it ensures the DB and app server are available and configured. Control plane: Client config, instance profile, transport domain, RFC destinations, job scheduling, and monitoring config. See Module 1.

Deployment and integration

Deployment: On‑premise and hosted: customer/partner installs and maintains. S/4HANA Cloud: SAP operates; customer has limited Basis tasks (e.g. transport for extension). Integration: STMS for transport between systems; SM59 for RFC (used by CPI, PI, other SAP systems). Link to Security (SU01, PFCG) and Integration (Module 29).

Example: Transport from development to production

A custom report is developed and must go live in production.

  1. Development (DEV): Developer creates report in DEV client 800; assigns to transport request N. Request is released. In STMS, the transport is exported (file on transport directory).
  2. Quality (QAS): Basis imports the transport into QAS. Test team validates. If OK, transport is released for production. (Some landscapes use a separate “release” step.)
  3. Production (PRD): Basis imports the transport into PRD during a maintenance window. Report is now in production. Security team assigns role/transaction so users can run it.

Result: Controlled promotion; no manual code copy. STMS and transport requests are the only path for ABAP and customizing.

Key concepts

Client: Self-contained unit; logon always includes client. Typical: 800 dev, 100 prod. Transport request: Container for objects; released = ready to export/import. STMS: Defines transport domain and queues; import is done from STMS. S/4HANA Cloud: SAP runs Basis; customer uses “Maintain Transport” and similar for extension content; no direct access to OS or DB.

📝 Module Quiz

Q1: Basis is primarily:

  • A) Sales module
  • B) System administration and control plane (client, transport, jobs)
  • C) Procurement only
  • D) Production only
Correct: B
Basis = technical foundation and admin.

Q2: STMS is used for:

  • A) Billing
  • B) Transport management (import/export between systems)
  • C) Only MM
  • D) Only SD
Correct: B
STMS = Transport Management System.

Q3: Client in Basis means:

  • A) Customer in SD
  • B) Self-contained logical unit for data and customizing
  • C) Only vendor
  • D) Only material
Correct: B
Client = logical system boundary (e.g. 800 dev, 100 prod).

Q4: What is SM59 used for?

  • A) Only sales order
  • B) RFC destinations (connectivity to other systems)
  • C) Only purchase order
  • D) Only material master
Correct: B
SM59 = maintain RFC and other connection destinations for system-to-system calls.
