Module 37: SAP Solution Manager / Cloud ALM

For beginners: ALM stands for Application Lifecycle Management: everything needed to run and evolve SAP systems—implementation, testing, change management, monitoring, incident handling, and upgrade. SAP Solution Manager (SolMan) is the traditional on‑premise ALM platform for ECC and S/4HANA on‑premise. SAP Cloud ALM is the cloud-native ALM service for SAP cloud and hybrid landscapes (S/4HANA Cloud, BTP, SuccessFactors, etc.). Both cover implementation (projects, templates), operations (monitoring, alerts), and services (incident, change, test management). Key terms: implementation project, monitoring, change request, Cloud ALM.

SAP Solution Manager has been the central hub for implementing and operating SAP systems for many years. SAP Cloud ALM is the strategic direction for cloud-first customers: it runs in the cloud, requires no on‑premise installation, and is optimised for S/4HANA Cloud, BTP, and other SAP cloud products. Both support project methodology (e.g. SAP Activate), testing, and operations.

Purpose and scope

Implementation: Manage implementation projects (phases, workstreams, tasks). Use and customise fit-to-standard templates (e.g. for S/4HANA Cloud). Track scope (process scope, country scope). Document business processes and link to configuration. Operations: Technical and business process monitoring. Alert when systems or key processes fail or degrade (e.g. failed jobs, interface errors, high error rates in order-to-cash). Dashboards for system health and business KPI. Service: Incident management (log, assign, resolve); change request management (change control, transport); test management (test plans, execution, sign-off). Integration with SAP Support (e.g. create support tickets, send diagnostics). Upgrade and maintenance: Maintenance planner, upgrade dependency checks, and documentation.

In plain terms: When you go live with S/4HANA Cloud, you use Cloud ALM to run your implementation project (tasks, fit-to-standard), run tests, and after go-live to monitor the system and handle incidents and changes. You don’t install anything on your own servers—it’s all in the cloud. For on‑premise S/4HANA or ECC, Solution Manager is still used for monitoring, change management, and implementation tracking.

Features in detail

  • Implementation projects: Create a project for a new implementation or major release. Break down into workstreams (e.g. FI, SD, MM) and tasks. Assign owners and dates. Link to process documentation and configuration (e.g. in SAP Activate). Track progress and scope. In Cloud ALM, projects are native and linked to SAP’s best practices and fit-to-standard.
  • Monitoring: Technical: system availability, performance, database, batch jobs, interfaces. Business process: monitor end-to-end processes (e.g. order-to-cash, procure-to-pay) with KPIs and exception alerts. Root cause analysis: drill from process to transaction to system. Cloud ALM gets data from cloud systems via built-in connectors; SolMan uses agents on-premise.
  • Incident and change management: Log incidents (errors, user issues); assign to support or development; track resolution. Change requests: document change, get approval, link to transport or cloud release. Test management: define test cases, execute (manual or automated), record results. Integration with SAP Support for sending incidents and receiving patches.
  • Fit-to-standard and best practices: In Cloud ALM, access to SAP’s process templates and scope items for S/4HANA Cloud. Compare your scope to recommended scope; use pre-configured content for testing and documentation. Reduces customisation and speeds implementation.
  • Integration and API management: Monitor integration flows (e.g. CPI/BTP). See which systems connect to which; monitor message throughput and errors. Useful for hybrid landscapes (S/4HANA + BTP + Ariba, etc.).

Data plane and control plane

Data plane: SolMan stores project data, monitoring metrics, incidents, changes, and test results in its own database (on‑premise). Agents on managed systems send metrics and collect diagnostics. Cloud ALM stores data in SAP’s cloud; data is collected via cloud connectors and APIs from S/4HANA Cloud, BTP, and other SAP cloud apps. Control plane: Configuration of monitoring scenarios (which metrics, thresholds), alert rules, and assignment of incidents/changes to support teams. Project templates and process scope are configured in the implementation project. No SPRO in the traditional sense—Cloud ALM is configured via its own UI; SolMan has its own configuration (Solution Manager setup).

Deployment and integration

Deployment: SAP Solution Manager runs on‑premise (typically one or more SolMan systems in the landscape, with agents on ECC/S/4HANA). SAP Cloud ALM is cloud-only (SAP-hosted); no customer installation. Cloud ALM is the recommended option for S/4HANA Cloud and hybrid cloud landscapes. Integration: SolMan connects to managed systems via agents (diagnostics, metrics). Cloud ALM connects to S/4HANA Cloud, BTP, SuccessFactors, Ariba, etc., via standard APIs and connectors. Both can integrate with third-party tools (e.g. Jira, ServiceNow) for incident/change.

Example: Implementing S/4HANA Cloud with Cloud ALM and handling an incident

Implementation: Company starts an S/4HANA Cloud implementation. In Cloud ALM they create an implementation project, select scope (e.g. FI, SD, MM, procurement). They use fit-to-standard to choose scope items (e.g. “Manage Customer Invoices,” “Manage Purchase Orders”). Tasks are generated (configure, test, train). Team runs test cases in Cloud ALM and records pass/fail. Go-live checklist is tracked in the same project. No SolMan installation is needed.

Incident after go-live: User reports “payment run failed.” In Cloud ALM, support logs an incident, links it to the affected system (S/4HANA Cloud). Monitoring shows the payment run job failed with a specific error. Support assigns to basis/functional team. Team resolves (e.g. corrects bank configuration) and closes the incident. If it were a software defect, they could create an SAP support message and attach diagnostics from Cloud ALM.

Key concepts

Cloud ALM is included with SAP cloud product subscriptions (e.g. S/4HANA Cloud); no separate licence in many cases. SolMan 7.2 is the current major version for on‑premise; SAP is focusing innovation on Cloud ALM. For hybrid landscapes, both can coexist: SolMan for on‑premise, Cloud ALM for cloud. Migration from SolMan to Cloud ALM for cloud systems is the typical path. Monitoring can be extended with custom metrics and dashboards.
