Module 41: SAP Activate Methodology

For beginners: SAP Activate is SAP’s standard implementation methodology for S/4HANA (and other SAP solutions). It gives you a repeatable sequence of phases, deliverables, and best-practice content so that projects don’t start from a blank page. It supports both cloud (S/4HANA Cloud, fit-to-standard) and on‑premise (including migration). Phases typically are: Discover → Prepare → Explore → Realize → Deploy → Run. You get access to process diagrams, scope items, configuration templates, test scripts, and migration content. Key terms: phase, fit-to-standard, scope item, best practices, roadmap.

SAP Activate is delivered as a combination of methodology (phases and workstreams), content (best-practice business processes and scope items), and tools (e.g. SAP Best Practices Explorer, solution builder, migration content in SAP Activate). It is used by implementation partners and customers and is aligned with Cloud ALM and Solution Manager for project and test management.

Purpose and scope

Discover: Explore the solution and business case; high-level scope and deployment option (cloud vs on‑premise, greenfield vs conversion). Output: decision to proceed, deployment choice. Prepare: Project kick-off, team, environment (e.g. cloud trial or on‑premise sandbox), access to best practices. Output: project plan, team ready, system access. Explore: Fit-to-standard workshops: compare business requirements to SAP best practices and scope items. Identify gaps (configure vs extend vs adopt process). Output: scope document, process design, list of scope items and gaps. Realize: Configure system (using best-practice templates where possible), develop extensions, integrate, migrate data (if not greenfield cloud), test. Output: configured system, tested, data loaded. Deploy: Final preparation, cut-over, go-live, hypercare. Output: live system. Run: Operate, optimise, iterate (new releases, new scope). Output: stable operations and continuous improvement.

In plain terms: Fit-to-standard means “first see how far we can get with SAP’s standard processes and scope items before customising.” In Explore, you run workshops and compare your requirements to SAP’s best-practice scope; you then decide what to adopt as-is, what to configure, and what (if anything) to custom-build. This reduces cost and speeds implementation.

Phases in detail

  • Discover: Workshops and demos to understand S/4HANA capabilities. Use SAP Best Practices Explorer and solution documentation. Decide deployment (S/4HANA Cloud vs on‑premise, conversion vs greenfield). Build business case and high-level timeline. No system build yet.
  • Prepare: Set up project structure (workstreams, roles). Provision environment: for cloud, often a trial or subscription; for on‑premise, install or request sandbox. Load best-practice content (process flows, scope items, configuration). Align with SAP Activate roadmap in Cloud ALM or SolMan.
  • Explore (fit-to-standard): Core of Activate for cloud. Run fit-to-standard workshops per process area (e.g. finance, order-to-cash, procure-to-pay). For each process, review SAP’s scope items and process steps. Mark what you need; identify delta (gap) to standard. Decide: adopt standard, configure (within standard), or extend (custom). Document in scope document and process design. Output: signed-off scope and configuration approach.
  • Realize: Build the solution. Configure using best-practice templates (pre-delivered in cloud; import in on‑premise). Develop extensions only where agreed (BTP, key user tools, or ABAP). Integrate with other systems (Ariba, Concur, etc.). For migration: run data migration (brownfield or conversion). Execute test cycles (unit, integration, UAT). Track in Cloud ALM or SolMan.
  • Deploy: Cut-over plan (freeze, final data load, go-live). Training and change management. Go-live support (hypercare). Handover to run organization. Post go-live: monitor, fix issues, stabilize.
  • Run: Ongoing operations. Adopt new S/4HANA releases (cloud: continuous; on‑premise: upgrade project). Add scope (new scope items, new processes). Use Activate content for “Run” best practices (e.g. release management, testing for upgrades).

Best practices and content

SAP Best Practices: Pre-defined business processes, scope items (packages of configuration and process steps), and documentation. Available for S/4HANA Cloud (by country and industry) and S/4HANA on‑premise. Scope items are the building blocks: e.g. “Manage Customer Invoices,” “Manage Purchase Orders,” “Record General Ledger Journal Entry.” You choose which scope items to activate. Migration content: For conversion and brownfield, Activate provides migration roadmaps, checklists, and content (e.g. data migration objects, custom code remediation). Tools: SAP Best Practices Explorer (browse content), SAP Activate methodology in SAP Signavio Process Explorer (process flows), Cloud ALM for project and test management. Solution Builder (for cloud) helps assemble scope.

Deployment and integration

Deployment: SAP Activate is methodology and content—it is not “deployed” but followed. Content is consumed from SAP’s delivery (Best Practices Explorer, cloud solution templates, migration packages). Projects are run in Cloud ALM (for cloud) or Solution Manager (on‑premise). Integration: Works with Cloud ALM (Module 37) for implementation projects, fit-to-standard, and testing. Works with migration tools (Module 40) for conversion and brownfield. Works with Signavio (Module 23) for process design and process mining. Partners and customers use Activate as the default for S/4HANA implementations.

Example: S/4HANA Cloud implementation using Activate

Discover: Company decides to move to S/4HANA Cloud. They attend Discover workshops and review scope for finance, SD, and MM. Decision: cloud, fit-to-standard first.

Prepare: Project team is formed; cloud subscription is provisioned. They access SAP Best Practices and create a project in Cloud ALM linked to Activate roadmap.

Explore: Fit-to-standard workshops: for “Order to Cash,” they review scope items “Manage Sales Orders,” “Manage Deliveries,” “Manage Billing.” They need all three; one gap: they need a custom field on sales order for “Campaign ID.” Decided: use key user extension (no code). For “Procure to Pay,” they adopt standard. Scope document lists 45 scope items; 2 small extensions.

Realize: Configuration is done using solution builder and best-practice templates (most scope items are pre-configured). Key user adds Campaign ID field. Integration to Concur for travel is configured. Testing: 3 cycles in Cloud ALM; defects fixed. No data migration (greenfield).

Deploy: Cut-over: master data loaded (customers, vendors, materials, G/L), opening balances posted. Go-live weekend; hypercare for 2 weeks. Run: Team runs operations; next quarter they add scope item “Intercompany Sales” using same Activate approach.

Activate phases (summary)

1. Discover — Explore solution, decide deployment, business case.
2. Prepare — Project setup, environment, best-practice content.
3. Explore — Fit-to-standard; scope and gaps.
4. Realize — Configure, extend, integrate, migrate, test.
5. Deploy — Cut-over, go-live, hypercare.
6. Run — Operate, optimise, new releases and scope.
Relationship to other modules: Module 37 (Cloud ALM / SolMan) hosts the implementation project and fit-to-standard. Module 40 (Migration) uses Activate migration content for conversion and brownfield. Module 30 (S/4HANA Overview) is the target solution. Module 42 (SAP Build) can be used for extensions during Realize.
