Module 29: Integration (PI/CPI)

For beginners: Integration is how you get data from one system to another—e.g. employee data from SuccessFactors to S/4HANA, or an invoice from Ariba to S/4HANA FI. CPI (Cloud Integration, on BTP) is where you design iFlows (integration flows): receive data from system A, map it to the format system B expects, and send it. On‑premise middleware is PI/PO. You do not store business data in CPI; you configure the path and mapping (control plane), and the actual data flows through. Key terms: CPI, iFlow, IDoc, OData, BAPI, Event Mesh.

Integration connects SAP and non-SAP systems. CPI (cloud) and PI/PO (on‑premise) provide routing, mapping, and connectivity—the control plane for integration.

Purpose and scope

Integration answers: “How do we get data and events from system A to system B?” Key areas: CPI iFlows: Design integration flow (sender adapter → mapping → receiver adapter). Example: S/4HANA sends cost center via OData; CPI maps to SuccessFactors format; CPI calls SuccessFactors API. IDoc: Intermediate Document—SAP’s document format for A2A and B2B (e.g. ORDERS05 for sales order). Outbound from S/4HANA; inbound to partner or another SAP system. BAPI/RFC: Call S/4HANA function modules from external systems or from CPI. OData/REST: Modern APIs; S/4HANA and cloud products expose OData. Event Mesh: Publish events (e.g. “Sales order created”); subscribers (CPI, BTP app) react. API Management: Publish, secure, and throttle APIs (Module 22).

Features in detail

  • CPI (Cloud Integration): Create iFlow in BTP. Sender: e.g. SFTP, HTTP, IDoc, OData, or timer. Message is transformed (mapping: XML, JSON, CSV). Receiver: e.g. S/4HANA (OData, RFC), SuccessFactors (OData), Ariba. Prebuilt content for many SAP-to-SAP scenarios. Monitor message processing in CPI.
  • IDoc: Outbound: S/4HANA creates IDoc (e.g. on document save); IDoc is sent to PI/PO or CPI (or directly to partner). Inbound: CPI/PI receives IDoc or file; maps to IDoc format; sends to S/4HANA for processing (e.g. create sales order). WE02 (IDoc list), WE19 (test inbound).
  • RFC (SM59): Remote Function Call—S/4HANA (or other system) exposes function modules; another system calls them via RFC destination. CPI can use RFC adapter to call S/4HANA. SM59 maintains RFC destinations in S/4HANA.
  • OData: S/4HANA and cloud products expose OData services. CPI and external apps call these for read/write. REST and JSON for cloud-to-cloud.
  • Event Mesh: Event-driven: S/4HANA (or SuccessFactors) publishes event; Event Mesh delivers to subscribers (CPI iFlow, BTP app). Decoupled, asynchronous.

Data plane and control plane

Data plane: Business data lives in source and target systems (S/4HANA, SuccessFactors, etc.). Integration middleware does not store it long-term; it moves and transforms it. Control plane: CPI iFlows, API Management policies, Event Mesh topics and subscriptions, and RFC/OData configuration define how data flows. See Module 1.

Deployment and integration

Deployment: PI/PO on‑premise; CPI on BTP (cloud). SAP recommends CPI for new and cloud scenarios. Integration: CPI connects S/4HANA with SuccessFactors, Ariba, Concur, CX, IBP, and non-SAP. Module 22 (BTP) and product-specific modules (13–23) describe the endpoints; this module describes the “how” (protocols, patterns).

Example: Replicate cost center from S/4HANA to SuccessFactors via CPI

When a cost center is created or changed in S/4HANA, it should appear in SuccessFactors for org structure.

  1. Trigger (S/4HANA): Cost center is created in S/4HANA (OM or API). Option A: S/4HANA sends event to Event Mesh (“Cost center changed”). Option B: CPI iFlow runs on schedule and reads new/changed cost centers via OData. Option C: S/4HANA calls outbound to CPI (e.g. REST).
  2. CPI iFlow: iFlow is triggered. It reads cost center data (from event payload or OData call to S/4HANA). Mapping: transform to SuccessFactors format (e.g. cost center as org attribute or custom object). Call SuccessFactors OData API to create or update the cost center. Handle errors (retry, alert).
  3. Result: Cost center exists in SuccessFactors. EC org structure and reports show the same cost center. Optional: reverse sync (SuccessFactors → S/4HANA) depends on scenario.

Result: One integration flow; two systems in sync without manual entry.

Key concepts and T-codes

IDoc: Intermediate Document—structure (control, data segments); outbound from SAP or inbound to SAP. WE02 (list), WE19 (inbound test). BAPI: Business API—stable interface to create/change/read business objects. CPI: Cloud Integration on BTP; iFlows replace many PI/PO scenarios. SM59: RFC destinations in S/4HANA for outbound calls. Event Mesh: Decoupled; publisher does not know subscribers.

  • D) Only MM

  • A) Only Fiori
  • B) Document-based integration (e.g. order, invoice exchange)
  • C) Only report
  • D) Only batch
Correct: B
IDoc = Intermediate Document for A2A/B2B messaging.

Q3: BAPI is:

  • A) Only table
  • B) Business API (programming interface to SAP logic)
  • C) Only IDoc
  • D) Only RFC
Correct: B
BAPI = Business Application Programming Interface.

Q4: Where does CPI run?

  • A) Only on-premise PI
  • B) On BTP (Cloud); part of Integration Suite
  • C) Only in S/4HANA database
  • D) Only in BW

CPI runs on SAP BTP as part of Integration Suite.
