Module 23: SAP Signavio

For beginners: Signavio is about understanding and improving how business processes actually run. Process mining (“what really happens?”) takes event data from S/4HANA or other systems (e.g. “order created,” “delivery posted,” “invoice sent”) and builds a picture of the real process—including bottlenecks, rework, and deviations from the ideal. Process Manager is for designing and documenting processes (e.g. in BPMN). Signavio is cloud and integrates with S/4HANA and BTP so you can mine real data and, with SAP Build Process Automation, automate improved processes. It does not replace ERP; it helps you see and improve how work gets done. Key terms: process mining, event log, Process Intelligence, Process Manager.

SAP Signavio provides process mining and process management. It integrates with S/4HANA and BTP for analysis and automation.

Purpose and scope

Signavio addresses: Process mining: “What actually happens?” Event log (case ID, activity, timestamp) from ERP or CRM is loaded; Signavio discovers the process model and shows variants, cycle time, and bottlenecks. Process modeling and governance: Design and document processes (BPMN); collaborate; link to Signavio Process Governance for policies and controls. Insights and KPIs: Dashboards on process performance (e.g. order-to-cash duration, rework rate). Integration with SAP Build Process Automation allows “design → mine → automate” so that improved processes can be automated on BTP.

Features in detail

  • Process Intelligence (process mining): Connect to S/4HANA (or SuccessFactors, etc.) to extract event logs (e.g. order created, order released, delivery created, billing done). Signavio builds process model from the data. View: process map, variants, cycle time, rework. Filter by segment, time, cost.
  • Process Manager: Model processes in BPMN; publish and share; link to risk and control (Process Governance). Collaborative process repository.
  • Process Governance: Link process models to policies, risks, and controls. Compliance and audit view.
  • Connectors: Prebuilt connectors to S/4HANA (e.g. order-to-cash, procure-to-pay event logs), SuccessFactors, and other sources. Event log format: case ID (e.g. order number), activity name, timestamp, optional attributes (cost center, amount).

Data plane and control plane

Data plane: Event logs (extracted from source systems) and process models/KPIs stored in Signavio. No direct DB in customer systems; data is pulled via connectors. Control plane: Signavio admin (tenant, connectors, users); BTP integration for SAP Build and events. See Module 1.

Deployment and integration

Deployment: Cloud (Signavio tenant). Integration: S/4HANA (event log extraction for O2C, P2P, etc.); SuccessFactors (e.g. hire-to-retire); SAP Build Process Automation (consume process models, trigger workflows); BTP (events, APIs). Connectors and APIs for extraction and for pushing insights back.

Example: Order-to-cash process mining with S/4HANA

Company wants to see how order-to-cash really runs and where it slows down.

  1. Extract event log (Signavio): Signavio connector to S/4HANA extracts events: for each sales order (case ID = order number), activities such as “Order created,” “Delivery created,” “Goods issue,” “Billing document created,” with timestamps. Optional: cost center, amount. Data is loaded into Signavio Process Intelligence.
  2. Process mining: Signavio discovers the process from the log. Output: process map (which steps follow which), variants (e.g. 60% go Order → Delivery → Billing; 30% have a return step). Metrics: average cycle time (order to billing), bottleneck at “Delivery created,” rework (loops). Dashboard: cycle time by region, by product.
  3. Improvement: Team identifies that orders without delivery block take 5 days; with block they take 12. They fix the block logic. Next month, re-mine to confirm improvement. Optionally, automate exception path with SAP Build Process Automation.

Result: Data-driven view of O2C; targeted improvement and optional automation.

Key concepts

Process mining: Use event data (case, activity, time) to discover the real process and measure performance. No modeling by hand—data drives the model. Event log: Each row = one event (e.g. “Order 10001234, Activity = Billing created, Timestamp = 2025-02-01 10:00”). Signavio vs SAP Build: Signavio = analyze and model; SAP Build Process Automation = execute workflows. They can be used together (model in Signavio, automate in Build).

Q4: What is an "event" in process mining?

  • A) Only a purchase order
  • B) A single step in a process for a case (e.g. "Billing created" for order 10001234 at a given time)
  • C) Only a G/L posting
  • D) Only a production order
Correct: B
Event = one activity for one case (order) at one timestamp; the log is many events.
