End-to-end flows

Business processes span multiple modules. Key flows:

  • Order to cash (O2C): SD sales order (VA01) → delivery (VL01N) → billing (VF01) → FI (accounts receivable, revenue). Document flow links order → delivery → billing → FI document. MM reduces stock on goods issue; CO gets cost of sales. Modules 3 (FI), 6 (SD), 5 (MM), 4 (CO).
  • Procure to pay (P2P): Requisition → MM purchase order (ME21N) → goods receipt (MIGO) → invoice verification (MIRO) → FI (vendor liability, expense/inventory). Three-way match: PO, GR, invoice. CO gets cost center from PO. Modules 3 (FI), 5 (MM), 4 (CO). Ariba (Module 15) can sit in front of MM for sourcing and PO.
  • Make to stock: Demand (SD or planning) → PP MRP (MD04, MD02) → planned order → production order (CO01) → goods issue (components), confirmation, goods receipt (finished product). MM and CO involved. Module 7 (PP), 5 (MM), 4 (CO). IBP (Module 19) can feed demand and planned orders.

Document flow and integration

Within S/4HANA, document flow links related documents: e.g. sales order → delivery → billing (VBFA or follow-up document fields); purchase order → material document → FI document. Use transaction “Display document flow” (e.g. from VA03, VL03N) or tables (VBFA for SD) to trace. Cross-system integration: Cloud products (SuccessFactors, Ariba, Concur, CX) and S/4HANA integrate via CPI (Module 29), APIs, and Event Mesh. Replication is often scheduled or event-driven; master data (e.g. cost center, employee) is kept in sync so that postings and reports are consistent.

Example: Trace one order to cash

Customer order 10001234: from order to cash in the books.

  1. SD: Order 10001234 (VBAK/VBAP) → Delivery 8000000123 (LIKP/LIPS) → Billing 9000000456 (VBRK/VBRP). In VA03 or VL03N, use “Document flow” to see the chain.
  2. FI: Billing created FI document: Debit AR (customer), Credit Revenue (and tax). Document number in BKPF/BSEG (or ACDOCA in S/4HANA). Link from VBRK to FI doc.
  3. CO: Cost of sales may post to CO (from material movement or billing). Profitability (CO-PA) can show revenue and cost by order/customer. One order drives SD, FI, and CO; document flow and account assignment connect them.

Result: One business event (customer order) reflected in multiple modules; traceable via document flow.

Best practices

  • Configuration over customization: Use SPRO and standard options first. Custom code (ABAP) and customizing (e.g. custom fields) increase upgrade effort and risk. Document all customizing and transports.
  • Clean core: For S/4HANA, extend on BTP (ABAP Cloud, SAP Build) and use released APIs. Keep S/4HANA core as standard as possible. Key user tools (e.g. in S/4HANA Cloud) for simple extensions.
  • Document and test: Test changes in development and quality before production. Use transport requests for all changes. Keep runbooks and integration documentation up to date.
  • Security and compliance: Design roles (PFCG) for least privilege (Module 27). Use GRC (Module 32) for segregation of duties (SOD), access recertification, and control monitoring where compliance (e.g. SOX) is required.
  • Learning path: Use SAP Learning Hub, certification paths (e.g. S/4HANA, SuccessFactors, BTP), and product documentation. Role-specific training (e.g. FI, MM, Basis) builds on this foundation. Revisit Module 1 and any module for reference.
